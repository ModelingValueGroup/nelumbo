Types & functors

Before any logic, Nelumbo lets you define syntax: which phrases exist and how they are built. Person :: Object declares a type and Male :: Person a subtype. Male ::= Piet, Jan declares constants of a type. A functor declares a new phrase with ::=: Person ::= father(<Person>) says that father(a person) is again a person, where each <T> is a hole for an expression of type T. A phrase whose type extends Root can stand on its own line as a sentence; give such a functor the precedence #0. These sections have no queries and no meaning yet: a sentence is right when it parses, and the editor underlines it in red when it does not.

import nelumbo.lang Person :: Object Male :: Person Female :: Person Male ::= Piet, Jan Female ::= Marie Person ::= father(<Person>) Sentence :: Root Sentence ::= <Person> knows <Person> #0 Piet knows Marie father(Marie) knows Jan

Marie knows Klaas does not parse: Klaas is declared as an Animal, and knows takes a Person. Klaas is a man: fix the declarations so the sentence parses.

import nelumbo.lang Person :: Object Male :: Person Female :: Person Animal :: Object Male ::= Piet, Jan Female ::= Marie Animal ::= Klaas Sentence :: Root Sentence ::= <Person> knows <Person> #0 Marie knows Klaas 
import nelumbo.lang
Person   :: Object
Male     :: Person
Female   :: Person
Animal   :: Object
Male     ::= Piet, Jan, Klaas
Female   ::= Marie
Sentence :: Root
Sentence ::= <Person> knows <Person> #0
Marie knows Klaas

Declare a type Thing with the constants flowers and a book, and a functor, so that both sentences parse.

import nelumbo.lang Person :: Object Person ::= Piet, Marie Sentence :: Root // declare a type Thing, its constants and a sentence functor so both sentences parse Marie gives flowers to Piet Piet gives a book to Marie

Patterns

A functor's pattern is more than words and holes. <(> really <)?> is optional, <(> likes <|> loves <)> is a choice, and <(> <Person> <,> , <)+> repeats a hole one or more times, separated by commas (<)*> allows zero times). The token types <NUMBER>, <STRING> and <NAME> accept a number, a quoted string or a name. Several alternatives of one type are separated by commas, each with its own precedence.

import nelumbo.lang Person :: Object Person ::= Piet, Jan, Marie, Klaas Sentence :: Root Sentence ::= <Person> <(> really <)?> <(> likes <|> loves <)> <Person> #0, <Person> is <NUMBER> years old #0, <Person> says <STRING> #0, party with <(> <Person> <,> , <)+> #0 Piet likes Marie Piet really loves Marie Klaas is 42 years old Marie says "hello" party with Piet, Jan, Marie

Piet can invite any number of guests, the last one after and. Change the pattern so all three sentences parse.

import nelumbo.lang Person :: Object Person ::= Piet, Jan, Marie, Klaas Sentence :: Root // change the pattern so all three sentences parse Sentence ::= <Person> invites <Person> #0 Piet invites Jan Piet invites Jan and Marie Piet invites Jan, Marie and Klaas 
import nelumbo.lang
Person   :: Object
Person   ::= Piet, Jan, Marie, Klaas
Sentence :: Root
Sentence ::= <Person> invites <(> <Person> <,> , <)+> <(> and <Person> <)?> #0

Piet invites Jan and Marie
Piet invites Jan, Marie and Klaas

Precedence

An operator is a functor whose pattern starts with a hole, like <Expr> plus <Expr>. When a sentence holds several operators, their precedence #N decides how they group: the higher binds tighter. With plus at #40 and times at #50, one plus two times three is one plus (two times three); operators of equal precedence group from the left. An operator without a precedence does not parse at all. A hole can carry a precedence too: <Expr#45> takes only operators above 45, so times but not plus. A hole without one takes the precedence of its functor; that is why the #0 of a sentence lets every operator in. The standard operators range from #16 (<->) to #80 (unary -).

import nelumbo.lang Expr :: Object Expr ::= one, two, three Expr ::= <Expr> plus <Expr> #40, <Expr> times <Expr> #50 Sentence :: Root Sentence ::= compute <Expr> #0, twice <Expr#45> #0 // one plus (two times three) compute one plus two times three // (one times two) plus three compute one times two plus three twice two times three

minus has no precedence, so the last sentence does not parse. Give it the precedence of plus.

import nelumbo.lang Expr :: Object Expr ::= one, two, three // give minus a precedence, the same as plus Expr ::= <Expr> plus <Expr> #40, <Expr> minus <Expr>, <Expr> times <Expr> #50 Sentence :: Root Sentence ::= compute <Expr> #0 compute three minus one times two 
import nelumbo.lang

             <Expr> minus <Expr> #40,
             <Expr> times <Expr> #50

Parentheses

Parentheses override precedence: (one plus two) times three. You never declare them: nelumbo.lang ends with Type P and P ::= (<P>) @nelumbo.lang.Parenthesized, one generic functor (see the next section) that gives every type its parentheses. The @ binds a functor to a Java class; Parenthesized hands back the expression inside, so (one) is just one, not a new phrase. A parenthesized expression is complete in itself, so it fits a hole of any precedence: twice (one plus two) parses where twice one plus two did not.

import nelumbo.lang Expr :: Object Expr ::= one, two, three Expr ::= <Expr> plus <Expr> #40, <Expr> times <Expr> #50 Person :: Object Person ::= Piet, Marie Person ::= father(<Person>) Sentence :: Root Sentence ::= compute <Expr> #0, twice <Expr#45> #0, <Person> knows <Person> #0 compute (one plus two) times three twice (one plus two) twice ((one)) (father(Marie)) knows (Piet)

Add square brackets as a second way to group expressions, so the last sentence parses. Bind them to @nelumbo.lang.Parenthesized too, so [one] is just one.

import nelumbo.lang Expr :: Object Expr ::= one, two, three Expr ::= <Expr> plus <Expr> #40, <Expr> times <Expr> #50 // add square brackets as a second way to group expressions Sentence :: Root Sentence ::= compute <Expr> #0 compute (one plus two) times three compute [one plus two] times three 
import nelumbo.lang
Expr     :: Object
Expr     ::= one, two, three
Expr     ::= <Expr> plus <Expr>  #40,
             <Expr> times <Expr> #50
Expr     ::= [<Expr>] @nelumbo.lang.Parenthesized
Sentence :: Root
Sentence ::= compute <Expr> #0
compute (one plus two) times three
compute [one plus two] times three

Generics

Type E declares a type parameter. With it, Team<E> :: Object declares a generic type and Team<E> ::= team of <(> <E> <,> , <)+> a functor for it: team of Piet, Jan is a Team<Person> and team of Rex, Tom a Team<Animal>. A hole names the team it takes: <Team<Person>> rejects a team of animals, <Team<E>> takes a team of anything. Write a generic type without spaces: Team<E>, not Team < E >. The parentheses of the previous section are declared this way, and so are List<E> and Set<E> of the collections.

import nelumbo.lang Person :: Object Person ::= Piet, Jan, Marie Animal :: Object Animal ::= Rex, Tom, Bello Type E Team<E> :: Object Team<E> ::= team of <(> <E> <,> , <)+> Sentence :: Root Sentence ::= <Team<Person>> plays against <Team<Person>> #0, <Team<Animal>> chases <Team<Animal>> #0 team of Piet, Jan plays against team of Marie team of Rex chases team of Tom, Bello

A team can only hold persons, so the last sentence does not parse. Make Team generic, so animals can form teams too.

import nelumbo.lang Person :: Object Person ::= Piet, Jan, Marie Animal :: Object Animal ::= Rex, Tom, Bello // make Team generic, so that animals can form teams too Team :: Object Team ::= team of <(> <Person> <,> , <)+> Sentence :: Root Sentence ::= <Team> plays against <Team> #0 team of Piet, Jan plays against team of Marie team of Rex plays against team of Tom, Bello

Connected tokens

Whitespace between tokens does not matter: the pattern <NUMBER> : <NUMBER> accepts 9:30 and 9 : 30 alike. Between <[> and <]> the tokens must touch: <[> <NUMBER> : <NUMBER> <]> accepts only 9:30. Use it for a literal written as several tokens, such as a time, a date or a decimal number, so it cannot be taken for an expression with an operator. <[> and <]> themselves do not appear in the sentence. The standard library writes 3.14, 2025-01-01 and 16#FF this way, and nelumbo.lang the head of a generic type like Team<E>.

import nelumbo.lang Person :: Object Person ::= Piet, Marie Time :: Object Time ::= <[> <NUMBER> : <NUMBER> <]> Sentence :: Root Sentence ::= <Person> arrives at <Time> #0 Piet arrives at 9:30 Marie arrives at 14:05 // Piet arrives at 9 : 30 does not parse

Declare a type Date for dates like 1990-05-17, written without spaces, so both sentences parse.

import nelumbo.lang Person :: Object Person ::= Piet, Marie Time :: Object Time ::= <[> <NUMBER> : <NUMBER> <]> // declare the type Date, with connected tokens like Time Sentence :: Root Sentence ::= <Person> arrives at <Time> #0, <Person> was born on <Date> #0 Piet arrives at 9:30 Marie was born on 1990-05-17 
import nelumbo.lang
Person   :: Object
Person   ::= Piet, Marie
Time     :: Object
Time     ::= <[> <NUMBER> : <NUMBER> <]>
Date     :: Object
Date     ::= <[> <NUMBER> - <NUMBER> - <NUMBER> <]>
Sentence :: Root
Sentence ::= <Person> arrives at <Time>   #0,
             <Person> was born on <Date> #0
Piet arrives at 9:30
Marie was born on 1990-05-17

Named patterns

A piece of pattern that recurs can get a name: pattern GUESTS ::= ... declares it, and <GUESTS> stands for its body wherever it is written, after the declaration. A named pattern is pure abbreviation: unlike a functor, it declares no type and builds no value. Here GUESTS is the guest list of the Patterns exercise, now shared by two sentences. nelumbo.lang uses named patterns itself, for instance pattern QNAME ::= <[> <(> <NAME> <,> . <)+> <]> for the dotted name after import.

import nelumbo.lang Person :: Object Person ::= Piet, Jan, Marie, Klaas pattern GUESTS ::= <(> <Person> <,> , <)+> <(> and <Person> <)?> Sentence :: Root Sentence ::= <Person> invites <GUESTS> #0, party with <GUESTS> #0 Piet invites Jan, Marie and Klaas party with Jan and Marie

Both sentences use <TIME>, which is not declared yet. Declare it as a named pattern for a time like 9:30, above the functor that uses it.

import nelumbo.lang Person :: Object Person ::= Piet, Marie, Klaas // declare the named pattern TIME, for a time like 9:30 Sentence :: Root Sentence ::= <Person> arrives at <TIME> #0, <Person> works from <TIME> to <TIME> #0 Marie arrives at 9:30 Klaas works from 8:00 to 17:30 
import nelumbo.lang
Person   :: Object
Person   ::= Piet, Marie, Klaas
pattern TIME ::= <[> <NUMBER> : <NUMBER> <]>
Sentence :: Root
Sentence ::= <Person> arrives at <TIME>          #0,
             <Person> works from <TIME> to <TIME> #0
Marie arrives at 9:30
Klaas works from 8:00 to 17:30

Scoping

A { } block is a scope. A functor declared private in a block exists only inside that block, nested blocks included. Without private, a declaration in a block is visible after the block too: the block alone hides nothing. Below, Max is private to the block and Piet is not. private is also how two functors with the same pattern are kept apart: declared side by side, the parser cannot tell which one a phrase means and reports a non deterministic pattern merge.

import nelumbo.lang Person :: Object Sentence :: Root Sentence ::= <Person> reads #0 { private Person ::= Max Person ::= Piet Max reads { Max reads } } Piet reads // Max reads does not parse here: Max is private to the block

Both functors are written friend(<Person>), one for a person and one for a dog, so they clash. Restrict each one to the sentence that uses it, so both sentences parse.

import nelumbo.lang Person :: Object Dog :: Object Person ::= Piet, Marie Sentence :: Root Sentence ::= <Person> reads #0, <Dog> barks #0 // these two functors clash: restrict each to the sentence that uses it Person ::= friend(<Person>) Dog ::= friend(<Person>) friend(Marie) reads friend(Piet) barks 
import nelumbo.lang
Person   :: Object
Dog      :: Object
Person   ::= Piet, Marie
Sentence :: Root
Sentence ::= <Person> reads #0,
             <Dog> barks    #0
{
    private Person ::= friend(<Person>)
    friend(Marie) reads
}
{
    private Dog ::= friend(<Person>)
    friend(Piet) barks
}

Rex is private to its block, so the last sentence does not parse. Make it parse without moving it.

import nelumbo.lang Person :: Object Dog :: Object Sentence :: Root Sentence ::= <Person> reads #0, <Dog> barks #0 { private Person ::= Max Max reads } { private Dog ::= Rex Rex barks } // make this sentence parse, without moving it Rex barks 
import nelumbo.lang
Person   :: Object
Dog      :: Object
Sentence :: Root
Sentence ::= <Person> reads #0,
             <Dog> barks    #0
{
    private Person ::= Max
    Max reads
}
{
    Dog ::= Rex
    Rex barks
}
Rex barks

Propositional logic

Nelumbo is three-valued: a query is true, false, or unknown. The result notation [facts][falsehoods] shows the two sides; [()][] means "true", [][()] means "false", and [..][..] means "unknown". Edit the document; the results update inline as you type.

import nelumbo.logic true & true ? true | false ? !false ? unknown & true ?

Make the query below come out true by changing only the operator (the expected-result annotation [()][] means the editor will underline a mismatch until it is true).

import nelumbo.logic false & true ? [()][] 
import nelumbo.logic

false | true ? [()][]

Facts & queries

Ground truth is asserted with fact. Objects and their functors are declared first (Person :: Object introduces a type, Boolean ::= ... a relation), then a query binds a variable and enumerates every matching answer. Facts are open: what is not asserted is not false, so the trailing .. in [(X=Jan),..] says more answers may exist.

import nelumbo.logic Person :: Object Boolean ::= friends(<Person>,<Person>) Person ::= Piet, Jan, Klaas fact friends(Piet, Jan), friends(Jan, Klaas) Person X friends(Piet, X) ?

Add a fact so that friends(Klaas, Kees) holds.

import nelumbo.logic Person :: Object Boolean ::= friends(<Person>,<Person>) Person ::= Piet, Jan, Klaas, Kees // add a fact here friends(Klaas, Kees) ? [()][] 
import nelumbo.logic
Person :: Object
Boolean ::= friends(<Person>,<Person>)
Person ::= Piet, Jan, Klaas, Kees
fact friends(Klaas, Kees)
friends(Klaas, Kees) ? [()][]

A function value can be asserted too. A function has exactly one value, so its fact is closed: after fact age(Piet)=40 the answer is [(a=40)] without .., and every other age is false. Statements run top to bottom, and each fact or rule only adds knowledge: unknown answers become true or false, open answers grow or close, and nothing already proven is withdrawn. Nelumbo is monotonic. Consistency is checked on the answers: a later answer agrees with an earlier one and knows at least as much, or the query reports an inconsistency. A second age for Piet is even rejected as soon as it is asserted. Only relations and function values can be asserted: fact !friends(Piet, Klaas) is an error.

import nelumbo.integers Person :: Object Person ::= Piet, Jan Integer ::= age(<Person>) Integer a age(Piet)=a ? fact age(Piet)=40 age(Piet)=a ? age(Piet)=41 ?

Give Jan an age so that both queries below hold.

Integer ::= age(<Person>)

Rules & recursion

A rule <=> defines how a functor is derived. For a function, == gives its value directly: fib(n) == e is short for fib(n)=f <=> f=e. if attaches a guard to each alternative, and a rule may reference itself to recurse. The classic Fibonacci rule has a base case for n<=1 and a recursive step for n>1. Ask for a function's value with a function query: fib(7) ? introduces its own result variable, so the answer lists the value without a name, [(13)][..]. It is the same as fib(7)=r ? with a declared Integer r.

import nelumbo.integers Integer ::= fib(<Integer>) Integer n fib(n) == n if n<=1, fib(n-1)+fib(n-2) if n>1 fib(7) ?

Define factorial so that factorial(5) = 120.

import nelumbo.integers Integer ::= factorial(<Integer>) Integer n // fix this rule so factorial(5)=120 (hint: 1 if n<=0, else n*factorial(n-1)) factorial(n) == n factorial(5) ? [(120)][..] 
import nelumbo.integers
Integer ::= factorial(<Integer>)
Integer n
factorial(n) == 1 if n<=0, n*factorial(n-1) if n>0
factorial(5) ? [(120)][..]

Adding a rule adds knowledge just like adding a fact. It can even add only falsehoods: below, adult(Jan) is unknown until a rule says that nobody younger than 18 is an adult. After that rule adult(Jan) is false, while the fact adult(Piet) still holds. The rule is silent where its guard fails, so it takes nothing away. Had Piet been 16, the query adult(Piet) ? after the rule would report an inconsistency with the fact.

import nelumbo.integers Person :: Object Person ::= Piet, Jan Integer ::= age(<Person>) Boolean ::= adult(<Person>) Person p fact age(Piet)=40, age(Jan)=12 fact adult(Piet) adult(Piet) ? [()][] adult(Jan) ? [..][..] // unknown: no fact, no rule adult(p) <=> false if age(p)<18 adult(Piet) ? [()][] // unchanged adult(Jan) ? [][()] // now false: only the falsehood side grew

Data types

Nelumbo ships built-in types - integers, rationals, strings, collections, datetime - each importable, with its own operators and functions. Declare a variable of a type, then let a query compute and bind it. Operators like + and functions like len come from the imported module.

import nelumbo.collections Set<Integer> s Integer i s={1,2,3} ? |{1,2,3}|=i ?

Relational KB

A knowledge base is facts plus rules over relations. Base facts (here pc, parent-child) are asserted directly; rules with quantifiers such as E[x] (there exists) and A[y] (for all) derive new relations from them. Below, the mother relation m is derived from pc via an existential over female parents. Because pc facts are open, Beatrix may have parents not asserted here: the answer ends in ...

import nelumbo.logic Person :: Object Male :: Person Female :: Person Boolean ::= pc(<Person>,<Person>), m(<Person>,<Person>) Person a, b Female x m(a,b) <=> E[x](pc(x,a) & b=x) Female ::= Juliana, Beatrix fact pc(Juliana, Beatrix) Person who m(Beatrix,who) ?

Add a father relation f that mirrors the mother rule, using E[y] over male parents, so f(Beatrix,who) finds Bernhard.

Custom DSL

Nelumbo is a meta-language: declare your own functors and patterns with an explicit precedence (#N) and natural-language statements and queries become first-class syntax. Here a rule makes the friends facts symmetric and transitive, then the phrase X is a friend of Y is declared as a Boolean pattern that reads as ordinary English.

import nelumbo.logic Person :: Object Boolean ::= friends(<Person>,<Person>) Person ::= Piet, Jan, Klaas Person a, b, c, Who friends(a,c) <=> friends(a,c) | friends(c,a) | E[b](friends(a,b) & friends(b,c)) Boolean ::= <Person> is a friend of <Person> #30 Person X, Y X is a friend of Y <=> friends(Y,X) fact friends(Piet, Jan), friends(Jan, Klaas) Who is a friend of Piet ?

A synonym phrase X knows Y has been declared but its rule is wrong (X knows Y <=> X=Y). Fix the rule so Who knows Piet lists the same friends as the phrase above.

import nelumbo.logic Person :: Object Boolean ::= friends(<Person>,<Person>) Person ::= Piet, Jan, Klaas Person a, b, c, Who friends(a,c) <=> friends(a,c) | friends(c,a) | E[b](friends(a,b) & friends(b,c)) Boolean ::= <Person> knows <Person> #30 Person X, Y X knows Y <=> X=Y fact friends(Piet, Jan), friends(Jan, Klaas) Who knows Piet ? [(Who=Jan),(Who=Klaas),(Who=Piet),..][..]

Transformations

A transformation rule ::> rewrites one construct into several. The attr declaration below expands - at declaration time - into a getter function o.name and a := setter that itself transforms into a fact on that function. Declaring attr Person name String then behaves as if both were written by hand.

import nelumbo.strings Root ::= attr <Type> <NAME> <Type> #100 Type OT, AT NAME AN attr OT AN AT ::> { AT ::= <OT>.AN #30 Root ::= <{OT,Literal}>.AN := <{AT,Literal}> #30 {OT,Literal} ol {AT,Literal} al ol.AN := al ::> { fact ol.AN = al } } Person :: Object attr Person name String Person ::= Piet Piet.name := "Piet" String n Piet.name=n ?
